## 1. Purpose — what this program does

This program cancels the whole current check-run selection, for all vendors. Every invoice in APDUE is put back to unpaid, any special discount that was taken (by `AP.SEL.INVSPC`) is backed out of the invoice discount and APHIST net, APDUE is emptied, and the check-run control record is reset. If checks were already printed, it warns the operator to void them but still cancels. It does NOT void check records, cancel a single vendor or invoice, or log who cancelled.

## 7. Bug suspects

- **Matrix too small (lines 5, 33, 35):** `DIM DUEREC(3)`, but the program references `DUEREC(5)`. In UniVerse, referencing a subscript beyond the DIM is a run-time "array subscript out of range" error, and on MATREAD the extra attributes go into `DUEREC(0)`. As written, the special-discount reversal the 2-4-03 change added back either aborts or never happens. **Confirm by test on the live system.** (AP.SEL.INVSPC dimensions DUEREC(5) correctly.)
- **Delete before reversal (line 31 vs 34, 36):** APDUE is deleted before APDIST and APHIST are rewritten. An abort in between loses the special-discount amount, and APDIST DISC stays permanently inflated.
- **Abort mid-run (lines 28–30):** a missing APDIST or APHIST record chains to ABORT, leaving some invoices reset and others not, with APCHK not reset.
- **Cancels with checks printed (lines 18–20):** it warns but does not block, and no void record is made.
- **APHIST key mismatch:** it uses the full APDUE/APDIST key for APHIST. AP.SEL.INVSPC's held-credit path uses `FIELD(key,'*',1,2)`. If keys have a third part, the wrong APHIST record is adjusted.
- **APHIST NET restore is partial (line 35):** it adds back only the special discount. It assumes the selection set APHIST NET; whatever value NET held *before* selection is not restored. This cannot be verified without AP9 (not in BP).
- **Header and screen disagree:** the header says "CANCEL ENTIRE INVOICE SELECTION"; the screen says "CANCEL ENTIRE PAYMENT". Cosmetic.

## 8. Schema-design notes for the CTO

- Modifies **CheckRun**, **CheckRunLine**, **VendorInvoice**, **InvoicePaymentHistory**.
- A check run should be a first-class entity with a status (draft → selected → printed → posted → cancelled) and per-line reversal, not "delete APDUE".
- Keep the special discount as its own field so a reversal never has to do arithmetic on the invoice discount.
- Missing audit: who cancelled, when, which check numbers were voided.
- Extract the AP check print/update programs (not in BP) before committing the AP schema.
