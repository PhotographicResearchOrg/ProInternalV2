## 1. Purpose — what this program does

This is the line-entry screen of manual PO entry. `IV46` calls it with the PO number and PO record after the header (vendor, date, terms) is set. The buyer adds, changes and deletes PO lines: product (or vendor catalog number), quantity and unit cost. The buyer can also attach an existing special order (pseudo-product 555), or flag a line as a special order. On Update it writes the PO record (IVPO) and copies each line's open quantity and cost onto the product (IVMST attr 20–23), which is how on-order is tracked. It can also overwrite the product's raw cost (IVMST 19) when a buyer changes a line cost. It does NOT assign the PO number or vendor (IV46), print the PO (the IV45 call is commented out), suggest quantities, enforce pack sizes, or capture special-order customers (the IV46.SPORD call is commented out).

## 7. Bug suspects

- **Wrong field in vendor warning (771):** the message prints `R(12)` (IVMST attr 12 = S/C percent) as "sold by vendor". It should show attr 5 or 37.
- **Vendor check compares different keys (770):** IVMST attr 5 is the PRO vendor group, while the PO vendor may be an APMST vendor number (IV46.07). For such POs the warning fires on every line, which trains buyers to press `I`.
- **Stale record written on not-found (332–361):** `MATWRITE MREC` is outside the `MATREADU ... THEN` block. If the product disappeared, the **previous product's record** is written under the new key.
- **Hard stop mid-save (287):** if IVMST `555` is missing, `STOP` runs after some IVMST records have been updated but before IVPO is written.
- **IVMST written before IVPO, no transaction (122, 128, 131):** a failure between the two leaves products showing a PO that does not exist, or with the old quantities.
- **On-order display excludes backorders (929–930):** `TEMP` holds 21 + 23 but the screen shows `ON.ORD` (21 only).
- **Mixed-currency order value (373–378):** yen and cent amounts are added together and suffixed `Y`.
- **Raw cost changed before save (204):** if the session drops before `U`/`E`, the new raw cost stays on the product with no PO saved and no log.
- **Special orders not released (212–249, 642–649, 725):** on `E` or line delete, IVSPORD attr 4 still points at this PO. The order cannot be attached to another PO (line 703) until someone fixes the record by hand.
- **Negative quantities accepted (855):** `NUM('-5')` is true, so a negative PO quantity passes and is synced to IVMST as negative on order.
- **Over-received lines resynced negative (321):** if a qty or cost is changed on a line with received > ordered, remaining is negative and written to IVMST 21/23.
- **Duplicate lines lose cost (324):** the last line's cost overwrites the earlier ones in IVMST 22.
- **First-match LOCATE (289, 333):** if the PO appears twice in IVMST 20 (possible via IV.ORD.REC.13), only the first position is updated or removed.
- **IDATE argument mismatch (560):** `CALL IDATE(FLD,ERRMSG)` passes 2 arguments to a 4-argument subroutine (`BP/IDATE`). Any PROMPTS field with code `IDATE` fails at run time.
- **Unreachable special-order distribution (960–963):** IV46.SPORD is never called, so IVSPORD customer data is no longer captured from PO entry.
- **READU/MATREADU silent-fallthrough:** the `MATREADU` calls have no `LOCKED` clause, so they wait rather than fall through. The 332 case falls through on **not found** with a stale buffer (above).

## 8. Schema-design notes for the CTO

- Entities: PO Line (product or non-stock item, qty, unit cost, currency), PO Line ↔ Special Order link, Special Order, Product Raw/Standard Cost, Product on-order (derived).
- The PO line is stored twice (IVPO 6–9 and IVMST 20–23). PIV2 should keep only PO lines and derive on-order. That removes label 70, the 555 bucket and the open/backorder split.
- IVPO attrs 14 and 18 are special-order links in code but FG.PCT and CBM in the dictionary. IVPO 21 is undocumented. Resolve before mapping the IVPO SQL copy.
- Unit cost needs amount + currency code. The `Y` suffix and the "bare integer = cents" MONEY rule must not survive migration; data should be checked for costs that were keyed in cents by mistake.
- Product raw-cost changes from PO entry need an audit row (who, when, old, new, PO) and probably a permission.
- Missing audit: line added/changed/deleted by whom and when, cost overrides, vendor-mismatch overrides (`I`).
- Non-stock / special-order lines need a real item reference (catalog number + description + vendor) instead of free text in the product column.
- Extract before schema commit: `IV46` (done by others), `IV46.9999`, `IV46.SPORD`, `IV45` (PO print), `IV52`/`IV.ORD.REC` (receipt side of special orders), and the PROMPTS record `IV46.PROD` (data).
